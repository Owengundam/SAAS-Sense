# SupplierSignal reviewer guide

This guide describes the candidate implementation. Fill in the actual Shopify listing, development-store test account/access path and deployed URLs before sending it to reviewers. Do not send credentials in this file.

1. Install SupplierSignal from its Shopify App Store listing when published. For preapproval testing, use the Shopify-supported development installation surface supplied separately by the owner. The public landing page does not ask for a shop domain.
2. Open the app from Shopify Admin. An authenticated shop without a verified plan reaches `/app/pricing`; follow its link to Shopify's hosted plan selection. Approve the configured Founding Pilot plan, return to `/app`, and confirm the watchlist loads. Declining plan approval leaves the pricing screen reachable.
3. Select a Shopify product variant in **Add supplier source**. Choose a safe product in the test store and a permitted public HTTPS supplier page displaying the exact matching product and supplier SKU/model. Supported supplier domains come from deployment configuration; the test URL and matching identifiers must be provided by the owner. Confirm the match and add the source. Product and variant IDs come from Shopify's picker and are checked through Admin GraphQL.
4. Run **Check** for one source. A successful matching capture establishes a baseline with evidence, timestamp and decision audit. A changed fact needs a second consistent observation before a change alert. An inaccessible, ambiguous or mismatched page shows uncertainty or a source error and does not become an inventory fact. The app never writes to Shopify inventory.
5. Use the scheduled monitoring control to opt in or pause. The release supports manual checks; scheduled jobs are available only after the owner enables and verifies the external scheduler, active plan and spending ceiling. No browser tab is needed once the external job is enabled. Do not infer daily coverage from an opt-in alone.
6. Use Shopify's plan management to cancel. Once the verified contract ends, new manual and background checks stop. Uninstall disables checks and removes revoked sessions. On reinstall, authenticate again and approve the plan if needed. A new install starts with no source history and scheduled checks paused.
7. Public support, privacy, terms and refunds URLs are `/support`, `/privacy`, `/terms`, and `/refunds`. They remain unavailable until the owner has completed and approved the facts. Their anonymous HTTPS access must be checked on the deployed candidate.

Expected test artifacts: sanitized shop ID and selected product/variant IDs, source and observation screenshots using non-sensitive data, a declined-approval retry, cancellation timing, duplicate and delayed webhook results, scheduler logs if enabled, and the deployed candidate's release identifier. Any external supplier account required for review must be arranged openly with Shopify; protected portals are not supported by this pilot.
